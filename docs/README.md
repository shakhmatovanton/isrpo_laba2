# Geometric Lib: unit-тесты

Набор unit-тестов для библиотеки **geometric_lib**, которая вычисляет площадь и периметр треугольника, квадрата, прямоугольника и окружности. Тесты написаны с помощью стандартного модуля `unittest` (Python 3). Исходный код библиотеки в ходе работы не изменялся.

## Структура проекта

```
isrpo_lab4/
    docs/
        README.md
    tests/
        TestCircle.py
        TestRectangle.py
        TestSquare.py
        TestTriangle.py
    circle.py
    rectangle.py
    square.py
    triangle.py
    README.md
```

## Запуск тестов

Все тесты из корня проекта:

```
python3 -m unittest discover -s tests -p "Test*.py" -v
```

Тесты одного модуля, например прямоугольника:

```
python3 -m unittest tests/TestRectangle.py -v
```


## Используемые формулы

Для вычислений используется значение π с точностью 15 знаков после запятой.

- Треугольник: S = a·h / 2, P = a + b + c
- Квадрат: S = a², P = 4a
- Прямоугольник: S = a·b, P = 2(a + b)
- Окружность: S = πr², P = 2πr

## Функции библиотеки

| Модуль | Функции |
|---|---|
| `triangle.py` | `area(a, h)`, `perimeter(a, b, c)` |
| `square.py` | `area(a)`, `perimeter(a)` |
| `rectangle.py` | `area(a, b)`, `perimeter(a, b)` |
| `circle.py` | `area(r)`, `perimeter(r)` |

Все параметры и возвращаемые значения имеют тип `float`.

## Покрытие тестами

Для каждой функции написаны тесты трёх типов:

- **позитивные**: проверка значения по формуле для обычных положительных чисел;
- **граничные**: нулевые значения;
- **негативные**: отрицательные, комплексные числа, строки, `bool`. 

Для треугольника дополнительно проверяется условие существования треугольника.

Всего 30 тест-кейсов: 7 в `TestCircle`, 7 в `TestRectangle`, 7 в `TestSquare` и 9 в `TestTriangle`.

## Ожидаемое поведение

Позитивные тесты должны проходить. На граничные и негативные входные данные функции должны выбрасывать `ValueError` (некорректное значение) или `TypeError` (некорректный тип).

## Результаты

Тесты выявили, что функции обрабатывают только корректные положительные числа. Для остальных входных данных исключения не выбрасываются, поэтому граничные и негативные тесты падают. Подробные результаты по каждому модулю приведены в отчёте.

Проваленные тесты здесь являются результатом тестирования, а не ошибкой в тестах: они документируют дефекты библиотеки.
